# Spark costs

Sparks are displayed to people; accounting and persistence use integer microSparks. One Spark is exactly 1,000,000 microSparks. Floating-point values never enter the ledger. Decimal display values are parsed to microSparks, and fractional calculated costs are rounded up only at the final charge boundary.

Every account receives one idempotent grant of exactly 100 Sparks (100,000,000 microSparks). Repeating account setup replays that transaction rather than issuing another grant.

Billing has two categories. Operation Billing charges a completed or durably accepted operation, using either a fixed capability price or trusted AI-action consumption. Usage Billing accrues for storage over time and quantity. Every public tool has one explicit fixed, action-priced, outcome-priced, or free operation policy. Tool pricing takes precedence over action pricing, so a tool and the AI action it invokes are never both charged. Fixed-price book creation and extension charge for durable queue acceptance; other fixed tools charge for successful operation completion.

Fixed debit rules also own their public name and short billing description. `costService.listCharges()` projects those rules, storage pricing, and the variable AI-usage notice into the strict public `/api/v1/costs` contract. Purchase, account, and referral grants are deliberately excluded from that debit-only response.

AI usage is metered from trusted invocation data immediately after provider results are known. Each successful action receives its own idempotent charge using a stable identity that excludes variable usage totals; usage and the calculated amount are stored as transaction metadata. Fixed tools are debited before work starts and refunded in full when their operation fails. Every authenticated priced execution requires a stable request key before tool work or provider work starts; unsafe calls are rejected instead of receiving a random key. Retries must reuse that key. Provider telemetry and operational events may explain a charge, but they are not balances and must not be summed as a ledger.

Storage is priced at exactly 30 Sparks per GB-month, using 1 GB = 1,000,000,000 bytes and a 730-hour billing month. Storage automation charges hourly and carries fractional microSpark remainders forward, so hourly boundaries do not lose or invent usage through repeated rounding. A connected inbox initial import costs exactly 100 Sparks, and each genuinely new incoming subscription email costs exactly 1 Spark. Provider API calls, ordinary refreshes, existing messages, and label-only changes are free.

Spark transactions are the immutable financial record. Each transaction stores its signed delta and resulting user balance. A debit or negative adjustment that would take the balance below zero is rejected atomically; Spark accounts never provide implicit credit. Historical `recurring-service` rows remain readable, but no current billing service creates them. Events describe product activity and can be retried, reordered, or retained differently; they must never be treated as the source of truth for a balance. An event may reference a ledger transaction, but emitting an event does not itself charge or grant Sparks.
